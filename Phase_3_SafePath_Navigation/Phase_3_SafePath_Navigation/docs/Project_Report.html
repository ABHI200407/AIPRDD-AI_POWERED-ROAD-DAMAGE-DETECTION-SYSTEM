Abstract

The increasing prevalence of road damage, such as potholes and surface degradation, poses significant safety risks to commuters, leading to vehicle damage and fatal accidents. Traditional GPS navigation systems optimize routes based on distance or traffic congestion but fail to consider the physical condition of the road surface. This paper presents Phase 3 of the AI-Powered Road Damage Detection ecosystem: SafePath AI, a novel road condition-aware routing system.

The proposed solution integrates real-time road hazard data, detected via a YOLOv8 computer vision model and crowdsourced citizen reports, with an advanced graph-based A* pathfinding algorithm to compute the safest possible routes. Built upon a robust full-stack architecture comprising a FastAPI backend, PostgreSQL with PostGIS for spatial analysis, and a React frontend, the system dynamically assigns penalty weights to road segments based on hazard severity and vehicle vulnerability profiles.

Experimental results demonstrate that the routing engine successfully processes paths with sub-500ms latency while significantly reducing exposure to critical hazards for high-risk vehicles like two-wheelers. SafePath AI bridges the gap between infrastructure monitoring and commuter safety, offering a scalable framework for smart city navigation.

Chapter 1: Introduction

1.1 Background

India accounts for over 10% of global road accident fatalities, with a significant portion attributed to poor road infrastructure and potholes. Existing navigation solutions like Google Maps and Waze are highly efficient at circumventing traffic congestion, but they treat all road surfaces equally. A road that is mathematically the "fastest" may be physically hazardous, causing severe damage to a vehicle's suspension or risking the life of a two-wheeler rider.

1.2 Problem Statement

There is currently no mainstream navigation engine that integrates micro-level road surface data (potholes, cracks) into its pathfinding algorithm. Furthermore, the vulnerability of different vehicles varies drastically; a pothole that is a minor inconvenience to a truck can be lethal to a bicycle.

1.3 Objectives

  1. To design an A* routing algorithm that factors in road damage severity.
  2. To create dynamic "Vehicle Profiles" (Bike, Car, Truck) that penalize hazards differently based on vehicle vulnerability.
  3. To build a real-time WebSocket layer that broadcasts new hazards to active drivers instantly.
  4. To provide municipal authorities with a dashboard for SLA monitoring and repair routing.

1.4 Scope of Phase 3

Phase 3 focuses entirely on the Navigation and Routing Engine. While Phase 1 handled the YOLOv8 model training, Phase 3 integrates that model into a FastAPI ecosystem utilizing NetworkX graphs, KD-Trees, and OpenStreetMap (OSM) data to generate Turn-by-Turn, safety-aware navigation instructions.

  • Database: SQLite (dev), PostgreSQL with PostGIS (prod), SQLAlchemy ORM

3.2 Functional Requirements

  • The system must calculate routes based on selected Vehicle Type (Bike, Car, Truck).
  • The system must provide 4 Routing Modes: Fastest, Smoothest, Safest, Safe_At_Night.
  • The system must detect duplicate hazard image uploads using Perceptual Hashing.
  • The system must generate Turn-by-Turn instructions based on bearing changes.

Chapter 4: System Architecture

The SafePath AI system follows a highly decoupled, service-oriented architecture.

4.1 Dual Frontend Architecture

The system utilizes two distinct React applications:

  • Citizen App: A mobile-first web app where users can report potholes, view the live hazard map, and request safety-aware routes.
  • Government Dashboard: A desktop-oriented command center for municipal bodies to view heatmaps, monitor SLA breaches (e.g., potholes unfixed after 48 hours), and calculate optimal routes for repair crews.

4.2 Backend Services (FastAPI)

The backend is divided into specialized services:

  • services/pathfinder.py: Manages the graph creation, KD-Tree indexing, and A* algorithm execution.
  • services/smart_routing.py: Handles the vehicle penalty logic and road health calculations.
  • services/fraud_detection.py: Ensures data integrity by rejecting duplicate citizen reports.
  • services/websocket_manager.py: Manages active connections to push live data.

Chapter 5: Implementation

5.1 Graph Construction and KD-Tree Indexing

To calculate a route, the system first queries the Overpass API to fetch OpenStreetMap (OSM) nodes and ways within a bounding box. These elements are converted into a NetworkX Graph. To efficiently map a user's GPS coordinate to the nearest road segment, a KD-Tree is constructed. This reduces the time complexity of coordinate snapping from O(N) to O(log N).

5.2 The Dynamic Penalty Formula

The core of SafePath AI is its custom edge-weighting logic. When a hazard is detected near an edge, a time penalty (in seconds) is added to that edge's weight, discouraging the A* algorithm from traversing it.

edge_weight += (severity^2) * 50 * vehicle_factor

The non-linear square of the severity ensures that a Severity 4 pothole (D40) is penalized drastically more than a Severity 2 crack (D10). The vehicle_factor acts as a vulnerability multiplier:

  • BIKE: 3.0x multiplier. Highly sensitive to all damage.
  • CAR: 1.0x multiplier. Baseline.
  • TRUCK: 0.4x multiplier. Heavy suspension ignores minor damage.

5.3 Route Modes

The user can adjust the routing aggressiveness via the penalty_mod variable:

  • FASTEST (0.1x): Accepts minor damage to ensure rapid arrival.
  • SAFEST (1.0x): Zero tolerance. Will take significant detours to avoid potholes.
  • SAFE_AT_NIGHT (0.5x): Balances pothole avoidance with keeping the user on primary, well-lit roads rather than detouring through dark alleys.

Chapter 7: Conclusion & Future Scope

7.1 Conclusion

Phase 3 of the AI-Powered Road Damage Detection project successfully demonstrates that modern routing engines must account for infrastructure health. By integrating computer vision data with a spatial A* graph, SafePath AI effectively protects vulnerable commuters from vehicular damage and fatal accidents. The system bridges the gap between crowdsourced hazard reporting and actionable, real-time navigation.

7.2 Future Scope

  • Live Traffic Integration: Merging SafePath's hazard data with Google Maps APIs to account for live traffic congestion.
  • V2X Communication: Broadcasting hazard data directly to smart-car dashboards via Vehicle-to-Everything protocols.
  • Toll Gate Integration: Gamifying the system further by offering automatic toll discounts to citizens who actively report and verify potholes on expressways.
  • Native Mobile App: Porting the React web application to React Native for optimized battery usage and background GPS tracking.
